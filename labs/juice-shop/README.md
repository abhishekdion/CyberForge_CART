# Local OWASP Juice Shop lab

This Compose setup runs Juice Shop in a local-only, egress-isolated Docker
network:

- The service has no published host port.
- Juice Shop uses an internal Docker network with no external routing.
- The short-lived CART runner shares Juice Shop's network namespace. Its
  `127.0.0.1` is the Juice Shop container itself, not the Windows host.
- CART's SQLite database is stored in a Docker named volume rather than on the
  Windows bind mount, avoiding SQLite locking issues across Docker Desktop's
  filesystem boundary. Reports are written to the repository.
- The app container is intentionally vulnerable. Keep this lab local and
  temporary; do not add a host port, proxy, tunnel, or router mapping.
- The image tag is `latest`, so it is mutable. Record the resolved image digest
  alongside any benchmark or ground-truth results.

## Requirements

- Docker Desktop with Docker Compose enabled.
- Docker Desktop with Docker Compose enabled and internet access to pull the
  official `python:3.13-slim` runner image on first use.
- CART source available at the repository root (mounted read/write for its
  temporary database and report output).

## Start and verify the lab

From the repository root:

```powershell
docker compose -f labs/juice-shop/compose.yaml up -d
docker compose -f labs/juice-shop/compose.yaml ps
docker compose -f labs/juice-shop/compose.yaml run --rm --entrypoint python cart-runner -c "from urllib.request import urlopen; print('HTTP', urlopen('http://127.0.0.1:3000/', timeout=5).status)"
```

The HTTP check runs from the shared container network namespace and should
return status 200. No host port is exposed.

Record which image was used:

```powershell
docker image inspect bkimminich/juice-shop:latest --format '{{.Id}}'
```

## Run CART against this instance

Use a separate database and report directory so the lab run does not mix with
other local CART data. Execute CART in the ephemeral runner, sharing only the
Juice Shop network namespace. The only selected address is its loopback
address, and only its application port is scanned:

```powershell
docker compose -f labs/juice-shop/compose.yaml run --rm cart-runner --db /state/cart-juice-shop.db select --prefix 127.0.0.1/32
docker compose -f labs/juice-shop/compose.yaml run --rm cart-runner --db /state/cart-juice-shop.db run --tier breach --ports 3000 --timeout 180 --report-dir reports/juice-shop
docker compose -f labs/juice-shop/compose.yaml run --rm cart-runner --db /state/cart-juice-shop.db status
```

`127.0.0.1/32` constrains the network worker to Juice Shop's own loopback
address inside the shared namespace. `--ports 3000` ensures CART does not probe
other services. The web worker recognizes 3000 as HTTP, uses the discovered
service port, and gates requests and redirects against the locked loopback
scope. Do not substitute a public address, broad LAN prefix, or organiser
target without explicit authorization.
The relative report path also lets a host-side CART dashboard find the report
artifact generated by the Linux runner.

## Stop and clean up

```powershell
docker compose -f labs/juice-shop/compose.yaml down
```

The `down` command removes the lab container and network but preserves the
SQLite named volume. After preserving any needed data, remove it with:

```powershell
docker compose -f labs/juice-shop/compose.yaml down -v
```

## Validation boundary

This lab makes local smoke testing possible; it does not itself establish
accuracy or a benchmark result. Before marking controlled validation complete,
record the image digest, CART commit, locked scope version, expected test
observations, run duration, audit-log results, and report. Verify that every
recorded network destination is loopback and that an out-of-scope test
destination is denied by unit tests rather than by probing a real external
system.
